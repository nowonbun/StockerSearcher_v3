# 기술적 후보의 웹 교차 검증

## 역할과 정보 시점

기술적 후보의 사실관계·데이터 품질·이벤트 위험을 확인한다. 호재·뉴스 점수로 종목을 새로 발굴하지 않으며 기술적 점수·과열 기준·순위를 변경하지 않는다. 부정확한 데이터나 확인된 거래 제한은 최종 추천 보류 사유가 될 수 있다.

- **가격 상한:** 시장별 실제 기준일의 확정 종가까지다. 당일 장중 가격으로 전일 계산을 덮어쓰지 않는다.
- **웹 정보 상한:** 오전 8시 점검이면 해당 점검일 `08:00 Asia/Seoul`까지 공개된 정보다. 별도 점검 시각을 지정하지 않은 일반 요청은 실제 요청 시각을 사용하고 보고한다.
- 과거 기준일 D만 지정한 재현 요청은 기본적으로 D 다음 달력일 `08:00 Asia/Seoul`을 웹 정보 상한으로 사용하고 이를 명시한다. 사용자가 별도 시각을 주면 그 시각을 적용한다.
- 웹 정보 상한 이후의 기사·공시·정정·결과는 사용하지 않는다. 현재 페이지가 나중에 수정되어 당시 내용을 복원할 수 없으면 그 역사적 항목은 검증불가다.
- 가격 기준일 이후부터 웹 정보 상한 사이의 공시는 ‘장 마감 후 확인된 위험’으로 분리한다. 예정 사건은 정보 상한까지 공개된 일정에 한해서만 미래 날짜를 기재한다. 발표 결과를 미리 아는 것처럼 쓰지 않는다.
- 공개/수정 시각, 사건 발생일·효력일, 조회 시각을 구분하고 가능한 한 KST/JST 또는 원문 시간대를 기록한다. 날짜만 있고 시각이 없어 오전 8시 이전인지 판단할 수 없는 당일 자료는 사용 가능하다고 단정하지 않는다.

## 검색 순서와 출처

시장별 기술적 상위 후보부터 한 종목씩 확인한다. 회사명뿐 아니라 **시장·종목 코드**를 함께 검색하고, 동명 회사·다른 시장·다른 종류주식이 아닌지 먼저 확인한다.

1. 공식 종목 페이지 또는 회사 IR에서 회사·코드·상장 시장을 대조한다.
2. 기준일 OHLCV를 제공하는 공식 또는 신뢰할 수 있는 독립 시세 자료와 MCP의 날짜·종가·거래량을 대조한다. 가능하면 거래소 자료를 우선한다. 한 사이트가 다른 사이트를 재전송한 자료는 독립적인 두 출처로 세지 않는다.
3. 웹 정보 상한까지 최근 30일의 공시·거래 관련 상태와 최신 유효 공지를 확인한다. 오래전에 시작한 거래정지·상장 관련 상태는 최근 30일에 기사가 없더라도 별도로 확인한다.
4. 당일과 향후 7일에 예정된 실적 발표·주주총회·권리 관련 일정 등을 확인한다. 미래 사건 자체가 아니라 **이미 공개된 일정**을 확인하는 것이다. 데이터 불연속이 관측되면 그 날짜의 기업행위까지 검색 기간을 확장한다.
5. 상승·거래량 급증 관련 보도를 보조 검색하고 공식 공시와 대조한다. 주가와 기사 시점이 비슷하다는 사실만으로 상승 원인·지속성을 확정하지 않는다.

출처 우선순위는 거래소·공시 원문 → 기업 IR → 원문 출처가 명확한 보도 → 기타 자료다. 게시판·SNS·검색 요약은 단서로만 사용하고 최종 확인 근거로 삼지 않는다. 단일 공식 문서가 해당 사실을 명시하면 문서 하나로 확인할 수 있지만 언론의 반복 전재를 다수의 독립 증거로 보지 않는다.

### 한국

- [KRX KIND 거래정지 확인](https://kind.krx.co.kr/investwarn/tradinghaltissue.do?method=searchTradingHaltIssueMain&paxreq=y)을 출발점으로 회사의 최신 공시·투자유의 상태 원문을 확인한다.
- 공시 검색에서는 KIND에서 연결되는 공식 공시 원문, 금융감독원 공시 또는 회사 IR을 우선한다. 기업별 검색은 `회사명 종목코드 공시 거래정지`, `회사명 유상증자 전환사채 주식분할`, `회사명 실적발표 일정`처럼 목적별로 나눈다.

### 일본

- [JPX TDnet 안내](https://www.jpx.co.jp/english/equities/listing/disclosure/tdnet/)에서 연결되는 적시공시·상장회사 검색, 거래소 공지 및 회사 IR을 우선한다. 보관 기간·문서 접근 범위 때문에 과거 자료가 검색되지 않을 수 있으므로 현재 결과만으로 과거 공시 부재를 단정하지 않는다.
- 일본어로도 `銘柄コード 会社名 適時開示`, `売買停止`, `株式分割`, `併合`, `増資`, `決算発表`, `上場廃止`를 목적에 맞게 검색한다. 번역된 설명과 원문 사실을 구분한다.

시세 차이는 먼저 수정주가·액면 단위·체결량 단위·시차·종가 종류 차이를 확인한다. 원인을 알 수 없는 차이를 MCP 또는 웹 중 하나로 임의 보정하지 않는다. 로컬 지표 재계산이 필요하면 새 기준을 명시하고 전체 기술적 조건을 다시 적용한다.

## 상태와 최종 분류

검증 항목마다 `확인`, `주의`, `보류`, `검증불가`, `해당 없음` 중 하나를 기록한다. 검색하지 않은 항목에 ‘해당 없음’을 붙이지 않는다.

- **최종 후보:** 종목 식별·기준일 가격 및 거래 관련 상태를 확인했고 보류/검증불가 핵심 항목이 없는 기술적 통과 후보. 표현은 ‘확인 범위 내 추가 경고 미발견’으로 제한한다.
- **주의 후보:** 식별·가격·거래 상태는 확인했으나 예정 발표·희석 사건 등 추가 주의가 확인된 후보. 경고를 붙여 별도 표시하며 사용자가 주의 후보 포함을 요청하지 않으면 기본 최종 5개에는 넣지 않는다.
- **보류:** 확인된 거래 제약, 설명되지 않는 가격 불일치·기업행위 왜곡 등으로 추천을 보류한다. 보류 사유·재확인 조건을 제시한다.
- **검증불가:** 공식 자료 접근 실패·시점 복원 실패·출처 불충분·웹 도구 부재. 기술적으로 통과해도 ‘잠정 후보’일 뿐 확인 완료 추천으로 표현하지 않는다.

기술적 순위는 남기고 최종 목록에서는 보류·주의·검증불가를 분리한다. 다음 기술적 후보를 검증할 수 있지만 시장별 기본 10개 한도를 넘어가면 먼저 범위 확대 여부를 확인한다. 제한에 도달했거나 통과 후보가 적으면 5개를 강제로 채우지 않는다.

## 증거와 실패 처리

- 후보별로 확인 항목, 판정, 핵심 사실, 원문 제목·링크, 공개 시각, 사건일, 미확인 사항을 남긴다. 검색어·확인 기간·접근하지 못한 사이트도 간단히 기록한다.
- 검색 결과 제목·요약만 보았으면 원문 확인 완료라고 쓰지 않는다. 정정 문서가 있으면 정보 상한 내에서 유효한 최신 문서를 기준으로 한다.
- 웹 도구 장애 시 MCP 기술적 결과를 보존하고 웹 검증 실패 원인과 재실행 조건을 보고한다. 조회되지 않은 공시를 ‘공시 없음’이라고 쓰지 않는다.
- 공개 자료의 확인은 읽기 전용이다. 계정 생성·유료 결제·문서 제출 등은 수행하지 않는다.
- 이 문서 작성 시 특정 후보 종목을 실검색하여 검증한 것은 아니다. 실제 종목 교차 검증·스킬 실운영·검증 규칙의 수익성은 **검증되지 않음**이다.
